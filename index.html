// interactive · ai quality

Eval Lab: be the LLM judge.

This is a small version of my day-to-day AI QA work. Three model answers were generated from one source. Mark each one PASS or FAIL for faithfulness, meaning every claim traces back to the source. Then run the judge and compare.

Source context (retrieved)

Metformin is a first-line medication for type 2 diabetes. It lowers blood glucose mainly by reducing hepatic glucose production. The most common side effects are gastrointestinal, such as nausea and diarrhea. It should be avoided in patients with severe renal impairment.

User question

“How does metformin work, and what side effects should I watch for?”

Faithful ≠ true. An answer can be medically correct and still fail if it adds a fact the source never stated.
Decompose, then score. Split the answer into atomic claims and check each one against the source. Fix the flagged claim; the overall score alone won't tell you what to change.
Mark all three answers, then run the judge.

QA-1042 · Bug S2 · High

iOS: Checkout “Pay” button stays disabled after saved card is re-selected when returning from 3-D Secure

Summary

After the user backs out of the 3-D Secure challenge and re-selects the same saved card, the Pay button never re-enables. The user can't complete the purchase without restarting the app.

Steps to reproduce
  1. Log in as qa+3ds@example.com, add any item to the cart
  2. Go to Checkout and select saved card •••• 3220 (3DS-enrolled test card)
  3. Tap Pay; the 3DS sheet appears
  4. Tap Cancel on the 3DS sheet
  5. Tap a different card, then re-select •••• 3220
Expected

Pay button becomes enabled once a valid card is selected.

Actual

Pay button stays disabled (isEnabled=false in the Appium inspector). No console error.

Evidence and notes
  • Reproduces 5/5 on iOS 17.5 (iPhone 15, BrowserStack) and 3/3 on a physical iPhone 12
  • Not reproducible on Android 14; this points at iOS-specific state handling
  • Screen recording and network HAR attached. The /payment-intents call is never re-issued after cancel
  • Regression: first build affected is 4.18.0 (412); 4.17.2 is fine

Risk-based plan: AI-generated study explanations

High risk
Hallucinated facts

Golden dataset + claim-level faithfulness judge on every prompt/model change. Release gate: 0 unsupported claims on the critical set.

High risk
Guardrail breaks

Adversarial set covering prompt injection, off-topic, and unsafe advice. Must refuse or redirect every time.

Medium
Retrieval regressions

Track context precision/recall on fixed queries. Alert when a re-index drops the right chunk.

Medium
Difficulty drift

Rubric-graded sample per release, checking that explanations match the learner level. Human spot-check on disagreements.

Low
UI / API plumbing

Standard automated coverage in CI: UI, API contract, and service layer. Smoke on every PR.

Exit criteria
Go / no-go

All high-risk gates green, no open S1/S2 defects, and judge agreement with human labels ≥ 90% on the calibration set.
